1. INTRODUCTION                                               *reviewer-intro*

nvim-reviewer shows what a branch changes compared with another one, in your
real editor: LSP, search and your usual mappings keep working.

- Each changed file opens as a normal buffer, read-only by default. Added
  lines are highlighted and removed lines are drawn in place, in red. The
  file itself is never modified.
- An oil-like browser lists the changed files one folder at a time. Read
  marks are text: change `[ ]` into `[x]`, then |:w|.
- Claude Code can comment every file, answer your questions about the code,
  and write a quiz, from the big picture down to single lines.

Requirements: Neovim 0.10 or newer, git, and Claude Code (`claude` on your
`PATH`, logged in) for everything that uses Claude. Without Claude Code,
reviewing and choice questions still work.

Claude calls go through `claude -p` and use your own Claude Code account and
usage. Code from the files you review is sent to Claude.

Run |:checkhealth| `reviewer` from inside a repository to check the setup.

==============================================================================
2. STARTING A REVIEW                                          *reviewer-start*

From anywhere inside a git repository:

  `:Review main feature`   review `feature` compared with `main`
  `:Review feature`        compare `feature` with the default base
                         (|reviewer-option-base|, `main` by default)
  `:Review`                continue the last review, or pick the branches

Branch names complete with <Tab>. They are read on the remote: `feature` means
`origin/feature` when it exists, so you review what was pushed. A name that
exists only locally is used as is; `refs/heads/feature` forces the local
branch. |:Review-fetch| gets the latest commits.

A review is identified by its two branches, `main..feature`. Read marks,
Claude's comments, quiz answers and questions are saved per review, so you
can come back to it later. When branches are built on top of each other,
review them one pair at a time.

                                                         *reviewer-checkout*
The files of a review must exist on disk at the version of the reviewed
branch, so that your LSP and search work on them:

- Your own checkout is used when it already is on that commit.
- Otherwise, one hidden checkout per repository (a git worktree in
  |reviewer-option-worktree_dir|) is created the first time, then moved to
  the reviewed branch at each new review. It is on no branch, so nothing done
  there can affect your branches. |:Review-clean| removes it.

                                                             *reviewer-deps*
The hidden checkout has no `node_modules`, so the LSP would miss the types of
external packages. The plugin installs them there from the lockfile (npm,
pnpm or yarn), skipping install scripts so no code of the reviewed branch
runs, and again only when the lockfile changes. Nothing is ever installed in
your own checkout. See |reviewer-option-deps|.

==============================================================================
3. THE BROWSER                                              *reviewer-browser*

`:Review` opens the browser in the current window, like `:Oil`. It lists the
changed files of one folder:
>
   userManagement → classManagement · src/backend/src/routes/ · 7/116 read
  [x] groups/  6/6
  [ ] M auth.ts  +3 −3
  [ ] D group.ts  +0 −32
  [x] M user.ts  +125 −185
<
- Folders show how many of their changed files are read.
- Files show their status (`A` added, `M` modified, `D` deleted, `R` renamed
  with `← old name`), lines added and removed, `✦` when Claude commented them.
- Deleted files are listed too; opening one shows its old content in red.
- The title bar shows the review, the folder, files read, the quiz score,
  and the preparation progress while |:Review-prepare| runs.

Moving around works like oil: <CR> enters a folder or opens a file in the
same window, `-` goes to the parent folder, `_` to the root of the review.
<C-s>, <C-h> and <C-t> open in a split or a tab, <C-p> previews, <C-c> goes
back to the file the window showed before the browser.

                                                      *reviewer-read-marks*
Read marks are text. Change `[ ]` into `[x]` (or back) with any edit: `rx`,
|.|, a visual block, |:g|, a macro. Then |:w| saves them. Changing a folder's
box marks every changed file inside it. |u| undoes until you save, and the
title bar shows `[+]` while there are unsaved marks. Any other edit is
ignored, with a message: |:w| only saves read marks, it never touches files.

`gs` switches between one folder at a time and all files in reading order
(see |reviewer-option-groups|). `g.` also lists unchanged files, dimmed, and
`gG` shows or hides generated files (|reviewer-option-generated|).

All the keys: |reviewer-keys-browser|. `g?` lists them in the browser.

==============================================================================
4. REVIEWED FILES                                             *reviewer-files*

Any buffer opened on a changed file of the review gets the overlay, however
it was opened (browser, |:edit|, a picker):

- added lines: highlighted, with a `+` sign;
- removed lines: drawn as virtual lines where they were, in red. They are not
  text: the cursor cannot go on them, search does not find them, line numbers
  skip them, and your LSP only sees the real file;
- Claude's comments, above the code they explain (|reviewer-claude|);
- a hint on the first line when the file has no comments yet.

The buffer is read-only (|reviewer-option-readonly|): an edit in the hidden
checkout would be on no branch, and an edit in your own checkout would change
your working copy. |:Review-edit| unlocks the current file if you need to.

                                                            *reviewer-split*
Side by side: |:Review-split| (`<leader>rs`) shows the version before the
change on the left and the file on the right, in Neovim's diff mode
(|diff-mode|); the inline overlay is off meanwhile. `→` moves both sides to
the next file. |reviewer-option-layout| makes it the default.

                                                            *reviewer-notes*
Your notes: `<leader>rm` (|:Review-note|) writes a note on the cursor line,
or on the selected lines in visual mode. A note stays on the line it was
written on, even inside a big changed block. Its text shows after a `✎` on a
virtual line just above that line. On a line with a note, the same
key edits it; saving it empty deletes it. Notes are saved per review, like
read marks, with the text of their first line, so they follow that line when
the code above it moves. |:Review-notes| (`gN` in the browser) puts every
note of the review in the quickfix list, and the browser shows `✎` after
files that have notes.

A note written `? ...` is a question (shown with `?`), `! ...` an issue
(shown with `!`); edit the prefix to change the kind. `<leader>rd` marks the
note under the cursor done (shown dimmed with `✓`). |:Review-notes| `open`
lists only the open questions and issues. |:Review-answer| has Claude
answer every open question in one call; `<leader>rh` on a question's lines
shows its answer. |:Review-export| puts the issues and open questions in a
Markdown buffer, to copy into the merge request yourself.

Keys in reviewed files: |reviewer-keys-file|. `↓`/`↑` (or `]c`/`[c`) move between changes,
`→`/`←` (or `]f`/`[f`) between files in reading order, `-` goes back to the browser on the
file's folder with the cursor on it.

==============================================================================
5. CLAUDE                                                    *reviewer-claude*

Claude only runs when you ask, unless |reviewer-option-ai| says otherwise.
When a review starts, the plugin shows what is already prepared and offers to
prepare it.

Comments on a file ~
`<leader>re` in a file, `gC` in the browser, or |:Review-explain| writes a
summary of the file, what changed, and a comment above each changed block.
They are saved per block. When the diff changes (a rebase, new commits), a
block whose content did not change keeps its comments, moved to its new
lines, and only new or changed blocks are commented again; a file whose
blocks all stayed the same is updated without calling Claude. |:Review-explain|!
writes every comment of the file again.

Preparing a review ~
|:Review-prepare| prepares the current review in the background:
  1. an overview: summary, main flows, key concepts, things to check
     carefully, and the role of each file (|:Review-overview|, `gO`);
  2. comments on every file, a few files per call, with the overview as
     context; Claude can open other files of the repo;
  3. a quiz. Each question is checked locally: every `file:line` reference
     must exist on the reviewed branch and every line of a code snippet must
     be in the referenced files. Questions that fail are dropped.
It can be stopped (`:Review prepare stop`, `gS`) and run again: files already
commented for the same diff are skipped. Each stage can run alone:
`:Review prepare overview`, `comments` or `quiz`. An existing quiz is kept
unless you add `!`. The cost reported by Claude Code is shown while it runs.

Questions ~
`<leader>ra` in normal or visual mode, or |:Review-ask|, asks Claude about the
file or the selected lines. Claude runs in the checkout of the reviewed
branch with read-only tools, so it can open any file of the repo. The answer
opens in a conversation window: `r` (or `i`) writes a reply, to ask for
details or a follow-up, and Claude answers in the same conversation. Replies
resume the same Claude Code session; when it cannot be resumed (deleted, or
the checkout moved), the conversation so far is sent again. Conversations are
saved: |:Review-asks| lists them, and you can reply to an old one.

What Claude sees ~
  overview      commits, file list, diffs, read access to the repo
  comments      the whole file with its changes, the overview, read access
  questions     the file with its changes, the selection, the overview,
                read access to the repo
  grading       the question, the reference answer, the code around the
                question's references

Models: |reviewer-option-claude|.

==============================================================================
6. QUIZZES                                                     *reviewer-quiz*

|:Review-quiz| opens the quiz of the current review. If there is none yet, it
offers to have Claude write it. `:Review quiz list` picks another review's
quiz, `:Review quiz mistakes` retries every wrong or partly right answer of
all quizzes.

Questions go from the big picture to single lines, in five levels:
architecture, flows and design, files and responsibilities, implementation,
line-level details. They have one answer, several answers, or an open answer
written in your own words, graded by Claude against a reference answer
(|reviewer-option-ai|: `grade_open_answers = false` to grade yourself).

After an answer, the quiz shows the right answer, an explanation, and the
code the question refers to: `1`-`4` open it. You can ask Claude for a hint
before answering (`gh`) or for an explanation after (`x`). Every answer is
saved with its history. Keys: |reviewer-keys-quiz|.

                                                          *reviewer-quiz-file*
Quizzes are JSON files `quiz-<base>..<branch>.json` in the repository's quiz
folder (|reviewer-data|). |:Review-prepare| writes them; you can also write
them yourself:
>json
  {
    "id": "main..feature",
    "title": "main → feature",
    "ref": "origin/feature",
    "questions": [
      {
        "id": "main..feature-q01",
        "level": 1,
        "topic": "Scope",
        "type": "single",
        "prompt": "What does this branch add?",
        "code": "optional snippet",
        "codeLang": "typescript",
        "choices": ["...", "...", "...", "..."],
        "answer": [1],
        "reference": "Short model answer (the full one for open questions)",
        "explanation": "Why",
        "refs": [{ "path": "src/app.ts", "line": 12, "endLine": 20 }]
      }
    ]
  }
<
`type` is `single`, `multi` or `open`. `answer` holds 0-based indexes and is
left out for open questions. Question ids must be unique across the quizzes
of a repository, because answers are saved by id.

==============================================================================
7. PROGRESS                                                *reviewer-progress*

|:Review-progress| shows every review of the repository with files read and
quiz results, your mistakes, and the questions you asked Claude. <CR> on a
line opens it: a review, a question to answer again, or an answer from Claude.
Keys: |reviewer-keys-progress|.

8. COMMANDS                                                *reviewer-commands*

:Review [{base}] [{branch}]                                           *:Review*
    Start a review and open the browser (|reviewer-start|). Every other
    command is a subcommand of :Review; `:Review <Tab>` lists them and the
    branch names. A known subcommand wins over a branch of the same name.

:Review start [{base}] {branch}                                *:Review-start*
    The same as `:Review [{base}] {branch}`, for a branch named like a
    subcommand.

:Review browse [{folder}]                                        *:Review-browse*
    Open the browser in the current window, at the root or on {folder}.

:Review split                                                     *:Review-split*
    Switch between inline changes and side by side (|reviewer-split|).

:Review next                                                       *:Review-next*
:Review prev                                                       *:Review-prev*
:Review next-unread                                           *:Review-next-unread*
    Open the next or previous file of the review in reading order, or the
    next unread one. The reading order is Claude's reading path when the
    overview has one (stages: architecture, then each flow, then details and
    tests), otherwise the groups (|reviewer-option-groups|). The browser marks
    the next file to read with `→ next`, and the folders or stage holding it, and a reviewed file shows its stage
    and what to look at above its first line. `:Review! prepare overview`
    writes an overview again, for one written before the reading path existed.

:Review read                                                       *:Review-read*
    Toggle the read mark of the current file.

:Review read-next                                               *:Review-read-next*
    Mark the current file read and open the next unread file.

:Review edit                                                       *:Review-edit*
    Allow changes in the current reviewed file (read-only by default).

:Review[!] explain                                              *:Review-explain*
    Write Claude's comments on the current file if it has none. With [!],
    write them again.

:Review comments                                               *:Review-comments*
    Show or hide Claude's comments.

:Review keys                                                       *:Review-keys*
    Show or hide the key bar at the bottom of the screen.

:Review about                                                     *:Review-about*
    Summary, what changed, and commits of the current file.

:[range]Review ask                                                  *:Review-ask*
    Ask Claude about the current file, or about the lines in [range].

:Review asks                                                       *:Review-asks*
    Your conversations with Claude; pick one to read it or reply.

:[range]Review note                                                *:Review-note*
    Your note on the cursor line, or on the lines in [range]. On a line that
    has a note, edit it; saving it empty deletes it (|reviewer-notes|).

:Review notes [open]                                              *:Review-notes*
    Every note of the review in the quickfix list, with its kind. With
    `open`: only the questions and issues not done.

:Review answer                                                   *:Review-answer*
    Claude answers your open questions without an answer, in one call
    (after asking). The plugin sends each question with the code around it.

:Review export                                                   *:Review-export*
    Your issues (done or not) and open questions as Markdown in a new tab,
    also copied to the unnamed register. No Claude call.

:Review[!] prepare [overview|comments|quiz|stop]              *:Review-prepare*
    Prepare the review in the background (|reviewer-claude|). With [!],
    write the overview, comments and quiz again. `stop` stops it.

:Review overview                                               *:Review-overview*
    Overview of the changes: summary, flows, key concepts, things to check,
    role of each file.

:Review quiz [list|mistakes]                                       *:Review-quiz*
    Quiz of the current review, another review's quiz (`list`), or every
    mistake to retry (`mistakes`).

:Review progress                                               *:Review-progress*
    Every review of the repository and what is remembered.

:Review fetch                                                     *:Review-fetch*
    `git fetch`, then show the latest commits of the reviewed branches.

:Review clean                                                     *:Review-clean*
    Remove the hidden checkout of the repository. Your progress is kept.

9. OPTIONS                                                  *reviewer-options*

Pass options to `require("reviewer").setup()`, or as `opts` with lazy.nvim.
Only what you set changes; lists replace the default list.
>lua
  require("reviewer").setup({
    repos = {
      myproject = { generated = { "^src/generated/" } },
    },
    keymaps = { file = { browse = "<leader>e" } },
  })
<
repos                                                *reviewer-option-repos*
    Optional settings per repository, keyed by the repository's folder name
    (or give `root` to match a path). Each can set `remote`, `base`,
    `generated`, `groups`, `worktree` and `quiz_dir`. Default: `{}`.

remote                                              *reviewer-option-remote*
    Branch names are read as `<remote>/<name>` when that ref exists.
    Default: `"origin"`.

base                                                  *reviewer-option-base*
    Base branch when |:Review| gets only one branch. Default: `"main"`.

worktree_dir                                  *reviewer-option-worktree_dir*
    Where the hidden checkouts go, one per repository.
    Default: `stdpath("cache") .. "/reviewer"`.

readonly                                          *reviewer-option-readonly*
    Reviewed files cannot be changed (|:Review-edit| unlocks one).
    Default: `true`.

layout                                              *reviewer-option-layout*
    `"inline"`: changes drawn in the file. `"split"`: before | after, in
    Neovim's diff mode. Default: `"inline"`.

deps                                                  *reviewer-option-deps*
    Dependencies of the hidden checkout (|reviewer-deps|).
    `install`         `false` to never install. Default: `true`.
    `ignore_scripts`  skip install scripts. Default: `true`.
    `cmd`             your own install command, e.g. `{ "npm", "ci" }`.
                    Default: from the lockfile.

show_comments                                *reviewer-option-show_comments*
    Show Claude's comments above the code. Default: `true`.

comments                                          *reviewer-option-comments*
    `"inline"`: comment boxes above the code. `"marker"`: the start of the
    comment on one virtual line above the code; `<leader>rh` opens the whole comment
    in a float, which closes as soon as the cursor moves. `<leader>rc` switches, `<leader>rh` works in either
    mode. `"hover"` is an older name of `"marker"`. Default: `"inline"`.

key_hints                                        *reviewer-option-key_hints*
    A one-line bar at the bottom of the screen with the most used keys of
    the current reviewed file, browser or quiz, like lazygit; `g?` lists
    them all. It is a real window, so
    it never hides code. |:Review-keys| hides or shows it. Default: `true`.

key_bar                                            *reviewer-option-key_bar*
    Which keys the bar shows, per buffer kind (`file`, `browser`, `quiz`),
    by keymap option name (|reviewer-option-keymaps|). `hide` leaves out keys you
    already know (from oil, for example); `show` adds keys that are only in
    `g?` by default. A next / previous pair is named by either option, and
    the browser's `[x]` + `:w` is `mark_read`. `g?` still lists every key.
>lua
    key_bar = {
      hide = { browser = { "open", "parent" } },
      show = { file = { "about" } },
    }
<
    Default: `{ hide = {}, show = {} }`.

inline_changes                              *reviewer-option-inline_changes*
    Inside a changed line, draw the changed words stronger, like GitHub.
    Default: `true`.

colors                                              *reviewer-option-colors*
    `"colorscheme"`, `"github"` (GitHub's diff colours, light or dark from
    'background') or `"vivid"` (a bright green and red mixed into the
    background of your colorscheme, so changes stand out on any
    background). Default: `"colorscheme"`.

show_removed                                  *reviewer-option-show_removed*
    Show removed lines in place. Default: `true`.

hide_generated                              *reviewer-option-hide_generated*
    Hide generated files in the browser (`gG` toggles). Default: `true`.

generated                                        *reviewer-option-generated*
    Lua patterns of generated files. Default: lockfiles of npm, yarn, pnpm.
    A repository's `generated` list is added to it.

groups                                              *reviewer-option-groups*
    Reading order: a list of `{ label, order, patterns }`. The first group
    whose Lua pattern matches a path wins; `order` sorts the groups.
    Default: database and migrations, shared code, backend, frontend, then
    tests, then the rest.

comment_width                                *reviewer-option-comment_width*
    Maximum width of a comment box. Default: `100`.

browser                                            *reviewer-option-browser*
    `view`            `"folders"` or `"reading"`: the first view. After
                      that, the browser opens in the last view used, kept
                      per repository across restarts. Default: `"folders"`.
    `icons`           icons from mini.icons or nvim-web-devicons, when
                    installed. Default: `true`.
    `show_unchanged`  also list unchanged files, dimmed (`g.` toggles).
                    Default: `false`.

float                                                *reviewer-option-float*
    `border`      border of floats. Default: `"rounded"`.
    `width`       fraction of the editor, or columns when > 1. Default: `0.8`.
    `height`      fraction of the editor, or lines when > 1. Default: `0.8`.
    `text_width`  wrap width of text in floats. Default: `96`.

symbols                                            *reviewer-option-symbols*
    `read` `"x"`, `unread` `" "`, `partly_read` `"-"`: browser checkboxes.
    `added` `"+"`, `removed` `"-"`: signs in reviewed files.
    `removed_prefix` `"- "`: before each removed line shown in place.
    `comment` `"✦"`, `pending` `"…"`, `note` `"✎"`.
    `next` `"→"`: the next file to read (browser) and the reading path line.

ai                                                      *reviewer-option-ai*
    When Claude runs:
    `on_start`            when a review starts: `"ask"` (offer to prepare
                        it), `"step"` (prepare it), `"never"`.
                        Default: `"ask"`.
    `comment_on_open`     comment a file the first time it is opened.
                        Default: `false`.
    `prefetch_next`       then also comment the next unread file.
                        Default: `false`.
    `offer_missing_quiz`  offer to write a missing quiz. Default: `true`.
    `confirm_prepare`     before preparing, show what will run (overview,
                        comments: files, calls and characters of code,
                        quiz) with a cost estimate from your past calls in
                        `usage.jsonl`, and ask. Default: `true`.
    `grade_open_answers`  Claude grades open answers; `false` to grade
                        yourself. Default: `true`.

claude                                              *reviewer-option-claude*
    `cmd`             the Claude Code executable. Default: `"claude"`.
    `models`          model per use: `overview` (`"opus"`), `comments`
                    (`"sonnet"`), `quiz` (`"opus"`), `ask` (`"opus"`),
                    `grade` (`"sonnet"`). An alias accepted by
                    `claude --model` or a full model name; `false` uses
                    your Claude Code default.
    `model`           for any use without its own model. Setting `model`
                    without `models` uses it for everything. Default: `nil`.
    `fallback_model`  used when the chosen model is busy or not on your
                    plan. Default: `"sonnet"`.
    `explain_tools`, `ask_tools`, `prepare_tools`
                    tools Claude may use; `""` for none.
                    Default: `"Read,Grep,Glob"`.
    `grade_tools`     Default: `""`.
    `batch_files`, `batch_chars`
                    size of one batch of files when preparing. Larger
                    batches cost a little less but get thinner comments
                    per file. Default: `8` files, `80000` characters.
    `gap_lines`       after the comments come back, blocks of at least
                    this many added lines that got no comment are sent to
                    Claude again, once, asking only for them. `0`: never.
                    Default: `5`.
    `effort`          effort per use (`overview`, `comments`, `quiz`, `ask`,
                    `grade`): `"low"`, `"medium"`, `"high"`, `"xhigh"` or
                    `"max"`, passed as `--effort`. A use left out lets
                    Claude Code choose. Default: `{}`.
    `mcp`             `false` passes `--strict-mcp-config`: your MCP servers
                    and connectors are not loaded. Default: `false`.
    `usage_log`       one JSON line per call (use, models, cost, turns,
                    tokens, prompt size) in `usage.jsonl` of the
                    repository's data folder. Default: `true`.
    `max_parallel`    calls running at the same time. Default: `2`.
    `timeout_ms`      Default: 10 minutes.
    `extra_args`      more arguments for `claude`. Default: `{}`.

keymaps                                            *reviewer-option-keymaps*
    Every key, per place: `file`, `browser`, `quiz`, `progress`, `float`,
    `input`. A key is a string, a list of strings, or `false` to disable it.
    Defaults: |reviewer-keys|.

==============================================================================
10. KEYS                                                        *reviewer-keys*

The browser and quiz defaults leave the keys that move the cursor or search
alone, so you move in them as in any buffer.

In reviewed files (`keymaps.file`), buffer-local      *reviewer-keys-file*
  `↓` `↑` `]c` `[c`  next / previous change              `next_change` ...
  `→` `←` `]f` `[f`  next / previous file                `next_file` ...
  `<leader>rr`     toggle read                         `toggle_read`
  `<leader>rn`     mark read, open next unread         `read_next`
  `<leader>ra`     ask Claude (normal or visual)       `ask`
  `<leader>re`     Claude's comments on the file       `explain`
  `<leader>ri`     about the file                      `about`
  `-`              browser on the file's folder        `browse`
  `<leader>rs`     inline / side by side               `toggle_split`
  `<leader>rc`     comments as boxes / markers         `comments_style`
  `<leader>rh`     comment here; again: go into it     `show_comment`
  `<leader>rm`     your note here (visual: the lines)  `note`
  `g?`             every key, in a float               `help`

In the browser (`keymaps.browser`)                 *reviewer-keys-browser*
  <CR>           enter a folder / open a file        `open`
  <C-s> <C-h>    open in a vertical / horizontal split `open_vsplit` ...
  <C-t>          open in a new tab                   `open_tab`
  <C-p>          preview                             `preview`
  `-` `_`          parent folder / root                `parent` `root`
  `gs`             folders / reading order             `toggle_view`
  `g.`             show unchanged files                `toggle_unchanged`
  `gG`             show generated files                `toggle_generated`
  <C-l>          refresh                             `refresh`
  `gC`             comment the file                    `explain`
  `gF`             comment the folder's files          `explain_folder`

11. HIGHLIGHT GROUPS                                      *reviewer-highlights*

follows your colorscheme. Override any of them with |nvim_set_hl()|.

12. SAVED DATA                                                 *reviewer-data*

Everything is kept between sessions, per repository, in
`stdpath("data")/reviewer/<repo>/`:

  `state.json`     shared settings: the last review, the browser view
  `reviews/<base>..<branch>/state.json`
                 that review's read marks, notes, quiz answers with their
                 history, questions asked to Claude, last file opened
  `reviews/<base>..<branch>/explain.json`
                 that review's overview and Claude's comments per file,
                 tied to the diff they were written for
  `quizzes/`       quiz files (|reviewer-quiz-file|)
  `usage.jsonl`    one line per Claude call (|reviewer-option-claude|)

A Neovim writes a review's files only when it changed that review, so two
Neovims on different reviews never overwrite each other. Data saved by an
older version (everything in the two top files) is moved into the review
folders on the next save.
